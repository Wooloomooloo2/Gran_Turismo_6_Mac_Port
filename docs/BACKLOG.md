## 2) Performance

- The lwcond waiter queue (patch 0005) is one lock and one condition variable for every lwcond; each signal wakes all waiters to check their own flag. Fine for boot; give each lwcond its own channel if a profile shows wakeup storms.

- Lifted PPU code is compiled at `-O1` (D30). Measure `-O2`/`-O3` compile time and frame
  time in milestone 5 (locked 60) and pick the level from that.

- RSX rectangle feedback (D70, batch 11 review M-5): each draw that samples a rectangle of its own target ends the Metal render pass, blits the rectangle into a new private texture and starts a new pass that loads the target (and depth) again; two units sampling one rectangle make two copies. On a tile-based GPU that is a write-out and reload of a 2048x2176 target per draw. Reuse `feedback_rect` while the surface's `color_serial` and the size are unchanged, pool the copies by size and format, and measure `s_ft_copies`/`s_ft_passes` per frame on the player page (PS3_FTRACE).
- Engine depth targets carry `MTLTextureUsagePixelFormatView` for the stencil view (D71), which may cost them lossless compression on Apple GPUs. Measure; if it matters, give the flag only to zetas that are ever read as A8R8G8B8.
- Zeta re-conversion per text run (D71, batch 12 review M-1): each of GT6's text runs marks the zeta written with its stencil draws, so its cover draw triggers a full 1440x1080 `depth_as_color`: a render-pass break (store and reload of colour and D32S8), a full-surface pass, a newly allocated `conv` texture (the old one is released, not reused) and a new `X32_Stencil8` view, times the text runs per frame. Reuse `conv` in place while its size and format hold, cache the stencil view per depth target, convert only the sampled rectangle (the cover draw's texture extent or scissor), and measure `s_ft_resolves`/`s_ft_passes` per frame on the player page.
- Present copy (D74): a display buffer smaller than its surface is copied into a texture of its size each present (1280x720, about 3.7 MB). Cheap, but a sampled sub-rectangle in the present pass (a UV scale in `eng_present_fs`) would avoid it once the frame dumps can read a region.
- Tree stamp breadth (D72, batch 12 review M-3): the stamp hashes the whole submodule, so a change that compiles nothing (a test, a tool, a doc, the runner sweep's rewrite of `scratch/ppu_conformance.cpp`) recompiles both images (about 5 min). Stamp a narrower hash for `OBJECT_DEPENDS` over the compiled paths only (`runtime/`, `libs/` without `tests/`, `include/`, `tools/host_window/`), and keep the full D47 hash for `gt6.image` and `boot_game`.

- Disc check against the community IRD file (per-file MD5s keyed by ISO sector; needs an ISO directory reader). Until then, the disc's GT.VOL is unverified against an independent source.
- Encrypted redump-style images plus disc keys or IRD files (needs a separate key-handling decision).
- Other regions (US BCUS-98394, Japan, Asia): per-edition hash manifests, update lists, address tables.
- Paid DLC needing PSN licence files or console-bound decryption.
- Player-side update download: fetch the updates directly, with TLS checked against Sony root certificates taken from the disc's update package, and without RPCS3 (spec section 6.1).
- Read the `.iso` directly. Today the player mounts it first (`hdiutil attach`, macOS only) and `gt6unpack` reads the mounted folder.
